## 1. 产品摘要

SuperTravelAgent 第一阶段要成为一个可由真实用户创建、查看和修改旅行方案的多 Agent 旅行规划 Web 应用，同时清楚体现总控 Agent、专业 Agent、工具调用、降级和校验等工程能力，用于个人实际使用和 AI Agent 相关实习/求职展示。

产品不是票务交易平台，不负责下单、支付或保证酒店/景点库存。它必须对火车票和航班等强实时信息保持诚实：查到就展示查询结果，查不到就给出官方入口和弹性方案，绝不编造。

## 2. 核心用户动作

用户通过结构化表单或自然语言输入创建一趟 1～7 天的单一主要目的地行程，查看多 Agent 规划过程和最终方案，再通过右侧工作台、地图或后续对话调整行程，最后下载 Markdown/PDF。

成功标准：用户无需理解 Agent 实现细节，也能完成“创建 → 生成 → 查看 → 修改 → 应用 → 下载”的完整闭环；面试官或招聘方能够从可折叠过程和项目结构看出这是真实的多 Agent 编排，而不是前端模拟状态。

## 3. 设计方向

- 产品界面采用克制型产品视觉，主题为已确认的“湖山青绿”方案 A。
- 核心色为深青绿，配合近白背景、墨绿色正文、薄荷色选中态和琥珀色风险提示；强调色只用于主操作、选中和状态，不做装饰性铺满。
- 场景句：用户在桌面端集中规划一趟真实旅行，需要长时间阅读文字、同时核对地图和调整日程，因此界面应以明亮、低干扰、信息可追踪为主。
- 视觉与交互锚点：已确认的主题预览 A、Ant Design 的标准控件语言、百度地图/Leaflet 的真实地图操作习惯。
- 使用一致的无衬线字体和紧凑层级；正文保持可读行长。卡片圆角控制在 12～16px 内，不使用渐变文字、装饰性玻璃拟态、嵌套卡片和无意义动效。

## 4. 产品范围

### 4.1 第一阶段包含

- 桌面端完整三栏旅行规划体验。
- 响应式移动端查看和简单编辑。
- 表单与自然语言两个独立创建入口。
- 3～4 个已验收旅行案例的预览与 Agent 过程回放。
- 复用现有 PowerPaint“旅行照片”P 图入口。
- 真实总控 Agent 和专业 Agent 任务编排。
- 国内与热门国际城市的单一主要目的地旅行。
- 真实地图、地点和路线联动。
- 工作台批量编辑、候选池、时间编辑、固定时间和智能优化范围。
- 活动卡片、相邻路段、真实地图和地点详情的三向联动。
- 总览、日程、候选、准备清单和提醒五个工作台主视图。
- 参考预算、提醒、轻量数字引用和来源列表。
- Markdown/PDF 下载。
- 匿名设备历史行程、删除全部旅程和单级正式版本恢复。

### 4.2 第一阶段不包含

- 登录、跨设备同步和分享链接。
- 原生移动 App。
- 多个主要城市串联的长线行程。
- 真实下单、支付和消费记账。
- 通用活动锁定、历史版本列表、归档和回收站。
- 多个行程在同一匿名设备上并发规划。
- 自动声称酒店或景点“当前可订/有票”。
- 攻略链接/截图自动导入、Chrome 插件和绕过用户审阅的自动排期。
- 系统推送、短信、邮件、日历同步和跨行程全局收藏。

## 5. 布局与信息架构

### 5.1 左侧

- 新建行程入口。
- “旅行照片”入口，进入现有 `/photo-editor` 与 PowerPaint 照片处理工作台。
- 当前与历史行程列表，每页 20 条。
- 规划中、已完成和降级完成等状态统一显示中文。
- 单个行程永久删除。
- 删除全部旅程；通过不可恢复确认对话框二次点击危险按钮后执行，规划运行中先阻止清空并提示停止当前任务。
- 用户画像、知识库和设置中的必要已有功能可以保留。

### 5.2 中间

- 新建状态：上方结构化表单参考用户上传图的清晰纵向层级、宽输入控件、偏好标签和克制留白，但继续使用“湖山青绿”主题并保留出发地、目的地、日期、三类人数、预算和偏好等完整字段。
- 下方自然语言输入与表单以“或”分隔；输入框上方显示 3～4 个可点击示例，点击先打开完整案例预览，再由用户点击“开始体验”进入三栏示例回放。
- 规划状态：通过 SSE 展示可折叠 Agent 工作过程，不展示原始思维链，也不把未校验的半截 JSON 当作正式方案。
- 完成状态：后端先校验完整 Schema，再通过 SSE 按章节渐进呈现最终旅行方案；Agent 过程默认折叠，修改输入框默认隐藏。
- 最终方案顺序固定：目的地与人文、去返程交通、住宿、分日行程与餐饮、预算与提醒、地图提示、下载入口、折叠参考来源。

### 5.3 右侧

- 完成状态必须完整展开上方真实地图和下方旅行工作台，因为正式方案已经包含地点、景点、餐厅和分日活动，需要立即展示三者对应关系；地图失败时也保留右侧结构并显示降级状态。
- 中间与右侧之间增加可拖动且支持键盘操作的垂直分隔条，设置双方最小宽度并提供恢复默认布局。
- 右侧下方工作台固定为五个主视图：“总览、日程、候选、准备清单、提醒”。地点详情是临时子视图，不增加第六个长期页签。
- “总览”展示行程摘要、每天主题和活动数、预算摘要、整体备注、未应用修改状态和主要提醒数量。
- 酒店推荐中确定一个“规划住宿点”作为路线基准，不代表用户已经预订；用户可以在总览中更换规划住宿点。
- “日程”按日期展示每日备注、活动卡片、相邻路段和“优化当天路线”；“候选”展示 Agent 为本次行程准备但未排期的 7～15 个备选活动。
- “准备清单”展示票务、证件、天气、装备和用户自建待办；“提醒”集中展示预约事项与固定时间冲突、营业时间风险、路线过载、预算偏差等规划约束。
- 预算详细内容从总览展开，来源继续放在中间最终方案底部的折叠列表，地图分组改为地图上的日期/类别筛选，不继续占用工作台主页签。
- 每张活动卡片使用一张固定 4:3 的代表图片，并显示序号、名称、时间、停留时长、地点类别、参考费用、固定时间提示、备注入口和必要操作；不在卡片中堆叠摘要、营业时间、地址、电话、游客评价、来源状态和核验标签。
- 相邻活动之间显示交通方式、距离和预计耗时；有可靠数据时可显示参考交通费用，路线失败时明确显示“路线信息待确认”，不绘制伪路线。
- 地点类别统一为景点、吃喝、交通、住宿、购物、休息/自由活动和其他；使用稳定内部枚举，前端只显示中文标签与低饱和类别色。
- 点击活动卡片或地图标记后，地图聚焦并高亮对应地点和路段，右侧下方切换到同一份地点详情；详情顶部提供“返回第 X 天”和“行程总览”，并恢复打开前的日期、滚动位置和地图上下文。
- 地点详情展示摘要、营业时间、地址、电话、最多三张图片、游客评价摘要和轻量“查看来源”入口；地图始终保留在上方。

## 6. 关键状态

协议和代码可以保留稳定英文枚举，但面向用户只能显示以下中文：

- `idle` → “待开始”或“等待补充信息”。
- `planning` → “规划中”，并显示阶段、任务、数据源摘要、耗时和状态。
- `completed` → “规划已完成”，表示完整 Schema 校验成功并保存。
- `completed/degraded` → “已完成，部分信息待确认”。
- `cancelled` → “规划已停止”，不生成正式快照。
- `error` → “生成失败”，并说明可以处理的原因和下一步。
- `draft` → “有未应用修改”，不能静默混入对话修改或导出。
- `demo_preview` → “案例预览”。
- `demo_replaying` → “示例回放中”，始终明确这不是新的实时查询。
- `demo_completed` → “示例回放完成”，地图和工作台完整展开。
- 地图、图片、来源、票务和导出都必须有加载、失败和诚实降级状态。

## 7. 核心交互

### 7.1 创建

- 表单必填：出发地、一个主要目的地、明确起止日期、成人/儿童/老人数和总预算；偏好可选。
- 日期选择器默认以用户时区的今天为开始日期，过去日期禁用，允许当天出发，只支持明确日期和 1～7 天区间。
- 自然语言信息完整时直接规划；缺少关键条件时显示可选择和自定义填写的澄清卡片。
- 示例优先复用项目已有旅行模板，后续只收录通过真实端到端验收且已去除临时价格和隐私数据的案例。

### 7.2 示例预览与回放

- 示例卡片只承担入口功能；点击后用标准预览对话框展示完整旅行需求、日期、人数、预算、偏好、案例特点和“开始体验”。
- 前端第一阶段可以使用静态案例数据完成卡片与预览；最终形态使用真实跑通、人工验收并脱敏的版本化案例包。
- “开始体验”后进入主三栏工作区，按照录制顺序播放 Agent 阶段、工具摘要、降级、最终方案章节、地图与工作台展开。
- 前端原型使用本地定时事件，最终后端以 SSE 输出录制事件；两者必须复用真实规划的事件结构和同一个前端事件归约器，不重新调用模型或实时 Provider。
- 回放提供暂停/继续、1 倍/2 倍、跳到最终结果和重新播放，并持续显示“示例回放”以及“案例录制时信息，仅用于演示”。
- 示例不写入真实历史，也不能直接保存修改；完成后提供“以此为模板创建行程”，把需求带入真实新建流程。

### 7.3 规划

- 总控 Agent 建立任务图，需求、研究、交通、住宿、美食、实时核验、路线、预算和质量校验各自返回结构化结果。
- 页面只展示可验证过程摘要，不展示原始思维链。
- Agent 阶段状态和最终旅行方案都通过 SSE 展示。后端先完成完整 Schema 校验，再把已校验 Schema 按章节发送 `final_plan_section` 事件，最终以 `trip_plan_completed` 激活地图、工作台、下载与正式快照。
- 一个匿名设备只允许一个活动规划；查看历史不停止后台任务，完成后使用状态圆点和约 5 秒站内通知。
- 完整旅行日默认安排午餐和晚餐；早餐只在用户明确需要、规划住宿不含早餐或当天很早出发时单独安排，到达日和离开日按照真实交通时间窗口决定餐次，不为凑数量强塞餐饮活动。
- 吃喝卡片不计入每天 4～5 个正式游览活动名额，但仍占用真实时间、路线和预算；正式餐饮必须绑定真实 `poi_id` 与坐标，备选餐厅进入候选池。
- 餐饮时间使用目的地当地用餐习惯、营业时间和当天路线综合确定，不把中国常用饭点硬编码到国际行程。
- 实时交通查询成功时，Agent 从已核验结果中选择一项主方案，正文默认展示主方案并折叠展示最多两项已核验备选；不能把搜索摘要或推测班次当作备选。
- 主方案始终标注“规划采用，未购票”。用户切换主方案后，系统重新计算首末日日程、车站/机场接驳、时间冲突和预算，并作为未应用草稿等待用户确认。

### 7.4 修改

- 桌面端允许拖拽、跨天移动、添加、替换、删除、备注和以 15 分钟粒度编辑时间。
- 整体行程和每张活动卡片均可填写备注；活动备注绑定 `activity_id`，移动到其他日期或候选池时继续保留。
- 修改先进入草稿，应用前只撤销最近一步操作；点击“应用修改”后一次性校验和重算，并在事务中保存新当前版本与上一次正式版本。
- 应用后可恢复到上一次正式版本，不提供历史版本列表；恢复会创建新的单调 `revision`，被撤销版本随即删除，不提供重做。
- 智能优化默认“保持地点和日期，只优化当天顺序、交通与时间”，必须由用户确认后执行。
- 每天顶部均提供“优化当天路线”快捷入口；优化只调整当天顺序、交通和非固定时间，不改变日期、不新增地点，也不能移动固定时间。
- 用户可将活动当前时间手动标记为固定时间；固定时间冲突阻止应用修改。
- 空档优先从候选池补充，候选不足时保留休息/自由活动，不自动搜索新地点。
- 第一阶段只保留一个“候选”业务状态，不再拆分推荐发现、收藏和候选池；Agent 为本次行程准备的备选地点直接进入候选视图。
- 活动移入候选池时保留图片、备注和预约提醒，但清除所属日期、时间段与固定时间；重新排入某天后由系统建议时间，用户可再次确认是否固定。
- 候选活动可以拖到当天的具体位置，也可以通过“加入第 X 天”交给系统选择空档；只指定日期时，系统按照距离、营业时间、预算和可用时间插入最合适位置，用户仍可在应用前继续调整。
- 当天不存在可行空档时，候选活动保留在候选池并显示冲突原因，不强行排入日程，也不自动删除已有活动。
- “应用修改”区分硬错误与软失败：固定时间冲突、非法时间、无效日期和结构不完整等硬错误阻止提交；路线、图片、游客评价、参考价格等外部数据失败时允许保存结构正确的降级版本，并显示“已应用，部分信息待确认”。
- 用户点击“应用修改”后不展示校验、路线、预算和保存的内部阶段，也不展示 Agent 过程；按钮只进入禁用加载状态并显示“正在修改…”，防止重复点击。
- 操作反馈在成功时显示“修改完成”，降级保存时显示“修改完成，部分信息待确认”；失败时保留草稿并直接定位首个硬错误。成功反馈之后仍按下述规则输出修改后的完整方案。
- 后端仍使用唯一 `operation_id`、幂等检查和事务提交保证重复请求不会生成多个版本，但前端只消费开始、完成和失败三个操作级状态，不展示细粒度进度事件。
- 应用成功后，中间对话必须追加一条新的助手消息，通过 SSE 按章节输出修改后的完整旅行方案，而不是只显示“修改完成”或局部差异；该消息复用首次规划的正式方案 Schema 和渲染组件。
- 新完整方案输出结束后，地图、工作台、当前正式快照和下载入口统一切换到同一 `revision`；对话中的旧方案保留用于回看，但标记“已被后续修订替代”，不能继续作为导出或编辑基准。
- 修改过程仍不展示内部处理阶段；“修改完成”只作为操作反馈，完整新方案是独立的结果输出。SSE 断线重连按事件序号续传，不得重复追加同一修订方案。
- 一个匿名设备只保留一份最新未应用草稿。草稿同步到匿名行程对应的后端会话，浏览器保存轻量镜像；刷新或重新进入时显示“发现未应用修改”，允许继续编辑或放弃。
- 未应用草稿不是正式版本，不进入历史版本列表，不覆盖当前正式版本或上一次正式版本；放弃草稿后不可恢复。
- 规划住宿点作为需要住宿日期的路线起点和终点，以轻量“从住宿出发/返回住宿”节点进入路线，但不计入每天 4～5 个正式活动；当日往返且无住宿需求时不生成住宿节点。
- 更换规划住宿点会重算所有受影响日期的首尾路线和交通预算，不把“规划住宿点”显示成已预订酒店。
- 用户新增景点、吃喝、住宿、购物或交通活动时，必须先从地图/搜索结果选择可解析到稳定 `poi_id` 和坐标的真实地点，才能应用到正式行程。
- 搜索不到准确地点的地点型活动保留在候选池并显示“地点待确认”；只有休息、自由活动、整理行李等不依赖地点的活动允许没有 POI，也不生成地图标记和路线段。
- 永久删除活动会同时删除关联活动备注、预约提醒、清单项、图片引用，并使相关路线段和地图标记失效后重算；确认框必须显示受影响的数据数量。
- 永久删除不可恢复。若用户希望保留活动资料、备注和提醒，应使用“移入候选池”，不能把删除隐式解释为暂存。
- 工作台草稿与对话修改冲突时，由用户选择先应用、放弃草稿或取消。

### 7.5 地图与移动端

- 卡片点击后地图居中并高亮；地图标记点击后工作台切换日期并滚动到卡片。
- 卡片、地图标记和地点详情共享稳定的 `activity_id/poi_id` 与同一份地点数据，不能出现三处内容不一致。
- 工作台处于“总览”时，地图显示全部日期的正式活动和分日路线；进入某一天后只显示当天正式活动和路线。
- 候选地点默认不进入地图；进入“候选”视图或用户主动开启“显示候选”后才显示，且不与正式路线连线。
- 总览地图使用日期颜色区分路线和标记外圈，标记内部使用类别图标；地点名称默认隐藏，只在选中、悬停或键盘聚焦时显示。
- 低缩放层级或地点密集时使用聚合标记；放大后再展开单个地点，避免标记和文字大面积遮挡。
- 拖拽期间只更新顺序编号，应用修改后才请求真实路线。
- 火车、航班等跨城交通的完整信息保留在中间最终方案与交通卡片中，目的地城市地图不绘制跨城全程路线。
- 去程到达车站/机场作为首日的轻量“抵达锚点”，返程车站/机场作为末日的轻量“离开锚点”，只接入目的地市内首段或末段路线，不计入每天正式活动数量。
- 只有实时工具核验成功的班次才能显示具体车次/航班、时刻、余票或库存；核验失败时锚点只表达“从车站/机场抵达”或“前往车站/机场”，不得补造具体班次。
- 移动端支持备注、固定时间、当天上移/下移和删除；不支持拖拽、跨天、候选池调度、替换或编辑时间。
- 移动端主导航固定为“对话、行程、地图”，不尝试压缩复刻桌面端三栏；活动详情在“行程”内以全屏页面打开。
- 活动详情中的“在地图中查看”切换到“地图”并聚焦对应地点；地图提供“返回活动名称”或“返回第 X 天”，返回后恢复原日期、原活动和列表滚动位置。

### 7.6 清单、备注与预约提醒

- 整体备注放在总览中，每日备注放在日期顶部，活动备注从卡片进入编辑并可在详情中完整查看；活动备注绑定稳定 `activity_id`，移动日期或进入候选池后继续保留。
- 准备清单与预约提醒共用统一的后端行动项模型和完成状态，前端按类型分别呈现在“准备清单”和“提醒”视图，不能维护两套互相矛盾的数据。
- 预约提醒不是订单状态。系统只能生成“需要确认、建议预约或建议购票”的行动项；只有用户手动处理后才显示“已处理”。
- 有可靠截止时间时显示目的地时区下的具体日期时间和来源入口；无法确认时显示“建议出发前再次确认”，不能编造预约开放日或余票。
- 第一阶段只提供应用内提醒，通过工作台角标与“提醒”视图显示待处理、临近和已逾期；不做系统推送、短信、邮件或日历同步。
- 关联活动移入候选池时提醒保留并标记“当前未排期”；活动被永久删除时同步删除关联提醒，并在删除确认中说明影响。
- 硬错误使用红色，软警告使用琥珀色；受影响活动卡片只显示一条简短原因，“提醒”视图展示完整问题列表，工作台顶部显示错误与警告数量。
- 点击任一问题后切换到对应日期、滚动并聚焦相关卡片或时间字段；应用失败默认定位第一个硬错误，不连续弹出多个模态框。

## 8. 数据真实性、内容和隐私

- 火车票和航班为强实时数据，不得编造；失败时保留车站/机场、接驳、弹性首尾日和官方查询入口。
- 酒店、景点、天气、营业时间、餐厅消费和介绍可以使用官网、地图、可信网页、攻略/小红书和本地知识库作为参考。
- 来源优先级：官方实时/官方静态同级，其次地图，再次可信网页与攻略，最后本地知识库；同级冲突依次按更新时间、多个独立来源一致性和保守结论处理。
- 正文使用全局连续、同源复用的青绿色可点击上标数字，底部来源列表默认折叠；不使用方括号 `\[1\]`。
- 酒店和景点可显示参考价格与预约建议，无实时结果时不能声称当前库存。
- 预算为软约束，即使超出容差仍生成完整方案并提示；国际价格保留原币和人民币参考换算。
- 图片来源、授权和更新时间必须保存在结构化数据中，但正文与活动卡片不单独显示图片来源文字。
- 每个活动保存 0～3 张有序图片和稳定 `cover_image_id`；卡片最多显示一张，详情最多显示三张。图片不足时按实际数量展示，不复制或使用无关图片凑数。
- 无可靠图片或全部图片加载失败时，卡片与详情都不渲染图片区域，让文字自然补位；不显示类别占位图。
- Agent 最终方案、活动卡片和详情图片分别使用固定宽高比、`max-width: 100%`、`object-fit: cover`、懒加载和溢出裁切，图片不能撑破所属容器。
- 地点详情使用“游客评价”作为标题，内容为 Agent 对地图、可信网页和攻略等公开反馈的简短摘要，不复制单个用户原文，不展示用户名，也不声称是平台官方结论。
- 游客评价允许使用比票务、库存更宽松的参考资料并接受一定概括误差，但不能脱离检索结果编造具体体验、排队时长、服务事件或卫生问题；没有可用反馈时隐藏该区域。
- 匿名行程保存至用户永久删除；禁止持久化身份证/护照、支付信息、密码、完整订单号和验证码，技术日志必须脱敏。

## 9. 运行约束与验收

### 9.1 重试与超时

- 单个专业 Agent 最多执行 2 次；工具重试和 Agent 重试分开记账。
- 相同 Provider、相同参数指纹最多调用 3 次，备用 Provider 最多额外 1 次。
- 快速工具 15 秒，实时交易类工具 25 秒，网页/攻略工具 35 秒，简单 Agent 45 秒，专业 Agent 90 秒。
- 整体 180 秒进入软超时并降低非关键实时性，300 秒硬超时后以规划完整性优先完成或明确失败。

### 9.2 导出

- Markdown/PDF 只从当前已应用的正式版本生成；不得混入候选池、未应用草稿、内部校验、Agent 过程、工具日志或历史正式版本。
- Markdown/PDF 均不附带正文来源角标或参考来源列表；来源只保留在网页在线查看界面中，PDF 不额外生成来源页。
- 导出包含整体备注、每日备注、活动备注、准备清单和预约提醒的正文内容，但不输出“待处理、已完成、已逾期”等应用内完成状态；导出是一份已认可方案，不是任务状态报表。
- PDF 保留目的地封面和每个正式活动的一张主图；图片使用固定比例、压缩和文件体积上限，缺图或图片获取失败时直接收起图片区域，不阻止文字方案导出。
- Markdown 只导出文字内容，不引用远程图片，也不嵌入 Base64 图片，保证单个 `.md` 文件可以独立迁移和长期打开。
- 相同当前修订与格式的文件缓存 10 分钟。
- 未应用草稿存在时，用户选择先应用再下载、下载已保存版本或取消。

### 9.3 时间与时区

- 国内行程的交通、活动、提醒和导出统一使用中国标准时间 `Asia/Shanghai`，界面简称“北京时间”，不随设备时区改变。
- 国际行程的跨境交通同时显示北京时间和对应境外当地时间；每个出发/到达时刻都带清晰的“北京时间/当地时间”标签，不能只显示两个无时区说明的数字。
- 用户抵达目的地后的分日活动、营业时间、预约时间和当天路线统一使用目的地当地时间；返程跨境交通继续并列显示北京时间与当地时间。
- 跨日交通明确显示完整日期和“次日”等提示。后端保存 UTC 时刻、带偏移量的 ISO 8601 时间以及 IANA 时区标识，前端按行程语境展示，不按浏览器设备时区静默改写。

### 9.4 验收

- 浏览器：最新版 Chrome、Edge；移动端按 390px 宽度验收。
- 表单生成国内 3 日行程。
- 自然语言缺失条件触发澄清。
- 示例卡片预览、开始回放、暂停/继续、加速、跳到结果、重放和“以此为模板创建行程”。
- 示例回放复用真实事件归约器，不调用模型或实时 Provider，也不写入真实历史。
- 火车/航班失败时无编造内容。
- 已核验交通结果支持一项主方案和最多两项折叠备选；切换后重算首末日日程、接驳和预算，并始终显示“规划采用，未购票”。
- 国际行程显示原币和人民币参考价。
- 完整旅行日按规则安排午餐和晚餐，餐饮不占正式游览活动名额；到达/离开半日不强塞餐次。
- 国内行程统一北京时间；国际交通同时显示北京时间和当地时间，目的地日程使用当地时间，跨夜日期清楚可辨。
- 工作台时间、拖拽、候选池、固定时间和地图联动闭环。
- 候选活动支持拖入具体位置和系统推荐空档；无可行空档时留在候选池并说明原因。
- 规划住宿点作为分日路线首尾锚点但不计入正式活动；更换后重算所有相关首尾路线。
- 地点型自定义活动必须绑定真实 POI，非地点型自由活动可以无地图数据。
- 永久删除确认展示关联数据数量，并级联删除备注、提醒、清单、图片、路线和标记。
- 应用修改的硬错误阻断、软失败降级保存，以及降级版本的明确状态提示。

- 应用修改成功后通过 SSE 输出修改后的完整方案；地图、工作台、正式快照和下载入口使用同一修订号，重连不会重复生成方案消息。
- 刷新后发现并恢复唯一未应用草稿，继续或放弃均不污染正式版本。
- 总览/单日/候选地图图层、密集标记聚合、按需地点名称和键盘聚焦。
- 卡片简短问题、提醒完整列表、顶部计数和一键定位首个硬错误。
- 工作台五个主视图、地点详情临时子视图以及“返回第 X 天/行程总览”的上下文恢复。
- 活动卡片、相邻路段、地图标记和地点详情三向联动且使用同一数据版本。
- 活动卡片单图、详情 0～3 图、无图收起区域及图片加载失败降级。
- 游客评价只展示可追溯的摘要，不复制用户原文，也不在无资料时生成内容。
- 准备清单与预约提醒共用状态，应用内提醒按目的地时区显示待处理、临近和已逾期。
- 总览备注和活动卡片备注在移动、应用与刷新后保持一致。
- 完成状态地图/工作台展开，水平与垂直分隔条满足鼠标和键盘调整且不压垮内容。
- 删除全部旅程二次确认、运行中阻止和后端事务清理。
- 当前与上一次正式版本的单级恢复。
- 停止规划、SSE 重连、软/硬超时降级。
- Agent 过程与最终方案的 SSE 顺序、断线补发、幂等和完成事件。
- Markdown/PDF 只导出当前已应用正式版本且不包含来源、候选、草稿、Agent 过程和内部日志。
- Markdown/PDF 保留旅客备注、准备清单和预约提醒正文，但不导出应用内完成状态。
- PDF 保留封面和正式活动主图且图片失败不阻断导出；Markdown 为纯文字单文件。
- 跨城交通不绘制全程地图路线，首尾日车站/机场轻量锚点只连接市内路线且不计入正式活动。
