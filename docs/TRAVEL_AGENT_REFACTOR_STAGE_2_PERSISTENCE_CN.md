# SuperTravelAgent 重构阶段 2：匿名持久化与版本

> 日期：2026-07-17
> 分支：`codex/travel-product-refactor`
> 状态：实现、自动验证与开发者真实页面验收已完成，等待用户确认

## 1. 本阶段结果

- 使用 Python 内置 SQLite 建立本地单实例持久化，启用 WAL、外键、事务和数据库迁移，不引入 Docker。
- 浏览器首次访问时获得高熵匿名设备令牌；数据库只保存令牌哈希，令牌通过 `HttpOnly`、`SameSite=Lax` Cookie 传递。
- 增加旅程列表、详情、保存、单条删除、全部删除和旧历史迁移接口；列表每页最多 20 条。
- 每个匿名设备只保留一个编辑草稿；正式方案只保存当前版和上一版，恢复上一版会生成单调递增的新修订号。
- 正式应用和恢复操作使用 `operation_id` 幂等回执，重复请求不会生成重复版本。
- 同一设备只能存在一个活动规划；活动规划期间阻止删除单条或全部旅程，公共 SSE 事件保留 5 分钟。
- 前端历史以服务端 SQLite 为事实源；原 `sage_chat_history` 自动迁移，成功后只保留轻量摘要镜像，失败时原始浏览器数据完全保留。
- 持久化前递归清理护照、证件、银行卡、支付、密码、验证码和订单等敏感字段；无标签长数字只有通过银行卡校验才脱敏，避免破坏网页文章 ID。

## 2. 用户可见效果

- 发送行程规划后，左侧立即出现旅程历史。
- 刷新页面后历史仍在；点击历史项会从后端恢复完整对话、正式方案和旅行工作台数据。
- 单条删除和“永久删除全部旅程”会真正删除服务端数据，不再只是清理当前浏览器缓存。
- 规划进行中时，同一匿名设备不能再启动第二个规划，也不能删除相关旅程；页面收到安全的中文冲突提示。
- 旧版浏览器历史会在首次加载时自动搬迁，不要求用户手工导入。

## 4. 开发者真实页面验收

在真实本地服务 `http://127.0.0.1:8001/` 中完成以下操作：

1. 输入“帮我规划一次北京1天文化之旅，预算500元，给出上午、下午和晚上的安排”。
2. 依次点击“北京本地出发”“日期还没定”“独自出行”“适中平衡”。
3. 页面生成 v1 正式方案、1 天状态、预算、来源、质量校验和旅行工作台。
4. 刷新页面后，旅程仍显示在左侧；点击后恢复完整对话、正式方案和工作台内容。
5. 通过旅程菜单和二次确认框永久删除测试旅程，列表恢复为空。
6. 浏览器控制台没有错误或警告；验收测试数据已清理。
